# 評価基準（criteria）の管理方法

このフォルダには、書類選考の評価ロジックが参照する基準データの**説明**のみを置きます。
基準データそのもの（具体的な評価ルール・スコアリング基準）は、機密情報のため
**このリポジトリにはコミットしません**（`.gitignore`で除外済み）。

## `/screen-entries`（エントリー段階・手動実行）が使う基準
- ファイル: `criteria/評価基準.xlsx`（ローカルのみに存在。Gitには含まれない）
- 「ランク基準」「希望人材」の2シートで構成
- ここに登録がない職種は、フォールバックとして`GET /v1/requisitions`の
  `requiredSkills`/`preferredSkills`/`personality`をそのまま評価基準として使う
- 更新したい場合は、このファイルを直接編集するか、Claude Codeに「〇〇職の評価基準を
  評価基準.xlsxに追加して、内容は...」と自然文で伝える

## `/screen-resume`（書類選考段階・毎日AM4:00自動実行）が使う基準
- Googleスプレッドシート「書類選考_社内基準（自動判定用）」を**実行のたびに直接参照**する
  （ローカルにもクラウドのルーティンにも、基準データのファイルは一切保存しない）
- 1行1条件のクリーンなテーブル形式（列: `カテゴリ, 自動判定, 条件, 対応, 理由文言, 備考`）
- **`自動判定`列が`FALSE`の行（年齢・外国籍・傷病休職歴・トランスジェンダー等）は、
  労働施策総合推進法・障害者雇用促進法・職業安定法の趣旨との関係で、AIによる自動判定
  （見送り等の判断・理由生成）を行わない。事実の提示のみに使う**
- 更新したい場合は、このスプレッドシートを直接編集する。編集内容は次回実行時から
  自動的に反映される（キャッシュ・同期処理は無い。毎回直接読みに行くため）
- センシティブな属性（年齢・国籍・障害/傷病等）に関わる新しい行を`自動判定=TRUE`で
  追加する場合は、実装（`.claude/commands/screen-resume.md`）側で一度立ち止まって
  Claude Codeに相談してから運用に乗せることを推奨する

## なぜGitにコミットしないのか
書類選考の具体的な合否基準（年齢・経験年数・職歴・働き方希望などに基づく判定ロジック）は
社内の機密情報であり、リポジトリの公開設定（Public/Private）に関わらず、Gitの差分・履歴に
残したくないためです。`.claude/commands/`配下には処理手順（ロジックの骨組み）のみを置き、
実際の基準値・判定ルールは常に外部（ローカルファイルまたはGoogleスプレッドシート）から
実行時に取得する設計にしています。
